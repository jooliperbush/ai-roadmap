# Traffic-first activation

User direction: launch the product and learn from traffic rather than conducting interviews.

The initial experience must distinguish a usable worked example from an actual provider audit. With zero providers configured, the primary CTA opens the existing no-signup worked example and the audit form is explicitly a demo. With providers configured, the primary CTA starts an audit. Existing form fields and backend behavior remain compatible.

Collect bounded, aggregate daily events for landing views, example views and primary CTA clicks. Persist only an allowlisted source and event count, with no visitor identifiers or raw URL/referrer. Honor Do Not Track for optional browser events. Audit requests already store source; accept an optional normalized source so accepted requests can be joined to real outcomes. Provide an operator-only CLI scorecard with request cohorts, completed live versus simulated/mixed reports, failures, insufficient evidence, and monitoring activation. Counts are not unique visitors, paid customers or proof of demand.

Keep interviews optional. Use a 14-day capped traffic test and explicit internal decision thresholds. Do not launch paid campaigns or send messages as part of this work.
